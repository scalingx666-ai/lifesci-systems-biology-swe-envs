<summary>Changelog</summary>
<p><em>Sourced from <a href="https://github.com/JuliaDocs/DocStringExtensions.jl/blob/master/CHANGELOG.md">DocStringExtensions's changelog</a>.</em></p>
<blockquote>
<h2><a href="https://github.com/JuliaDocs/DocStringExtensions.jl/releases/tag/v0.10.0">v0.10.0</a> - 2026-10-14</h2>
<h3>Breaking</h3>
<ul>
<li><code>@template</code> rejects a category no docstring belongs to, such as a misspelled name, with an <code>ArgumentError</code>. It used to store a template that never applied, so a package with such a category now fails to precompile until the category is corrected or removed (<a href="">#223</a>)</li>
<li><code>@template</code> throws an <code>ArgumentError</code> for a template string without <code>$(DOCSTRING)</code>, including a plain string literal, when the template is defined. Some of these templates used to load and fail with a <code>MethodError</code> only when Julia displayed a docstring. A package that defines one now fails to precompile (<a href="">#151</a>)</li>
<li>More docstrings get a template, and some get a different one. A docstring now gets its template when it sits in the same <code>begin</code> block as the <code>@template</code> (<a href="">#288</a>), documents a bare existing name such as <code>&quot;...&quot; f</code> (<a href="">#291</a>), or documents a parametric type's constructor (<a href="">#226</a>). A method defined through a <code>const</code> alias gets <code>METHODS</code> where it got <code>CONSTANTS</code> (<a href="">#289</a>). A function named like a macro, such as <code>var&quot;@f&quot;</code>, no longer gets <code>MACROS</code> (<a href="">#263</a>). Bindings documented together each get their own category's template (<a href="">#210</a>). Where a docstring repeats by hand what its template prints, the text now appears twice</li>
</ul>
<h3>Added</h3>
<ul>
<li>Add <code>TYPEDMETHODLIST</code>, which lists methods like <code>METHODLIST</code> but with argument and return types. <code>TypedMethodList(returns = false)</code> leaves out the return types (<a href="">#150</a>, <a href="">#197</a>)</li>
<li>Add <code>TypedMethodSignatures(returns = false)</code>, which renders typed signatures without return types (<a href="">#159</a>, <a href="">#179</a>)</li>
<li>Add a <code>returns</code> option to <code>MethodSignatures</code> and <code>MethodList</code> that follows each signature with its inferred return type. <code>MethodSignatures</code> and <code>TypedMethodSignatures</code> also take a string, such as <code>returns = &quot;success::Bool&quot;</code>, which they print after <code>-&gt;</code> in place of the inferred type (<a href="">#206</a>, <a href="">#246</a>)</li>
<li>Add the <code>DOCSTRINGEXTENSIONS_RETURN_ARROW</code> and <code>DOCSTRINGEXTENSIONS_SIGNATURE_WIDTH</code> environment variables. A reader sets them to change the arrow before return types, such as to <code>→</code>, and the width at which a signature wraps to one argument per line, 60 by default (<a href="">#252</a>, <a href="">#267</a>)</li>
<li>Add a <code>defaults = true</code> option to <code>MethodSignatures</code> and <code>TypedMethodSignatures</code> that prints default argument values, with the methods generated for positional defaults collapsed into one signature (<a href="">#19</a>, <a href="">#107</a>, <a href="">#194</a>)</li>
<li>Add a <code>defaults = :brackets</code> option to <code>MethodSignatures</code> and <code>TypedMethodSignatures</code>. It prints the collapsed signature without default values. Each optional positional argument appears in brackets. Any other symbol passed as <code>defaults</code> throws an <code>ArgumentError</code> (<a href="">#206</a>, <a href="">#247</a>)</li>
<li>Add <code>PUBLIC</code> to list a module's public names, both exported and declared <code>public</code> (<a href="">#190</a>)</li>
<li>Add <code>INSTANCES</code> to list the instances of an enum with their values. It supports <code>@enum</code> and EnumX.jl's <code>@enumx</code> (<a href="">#171</a>)</li>
<li>Add <code>SUBTYPES</code> to list the direct subtypes of a type as links. It lists only subtypes defined in the type's own module or a module inside it (<a href="">#47</a>, <a href="">#154</a>, <a href="">#227</a>)</li>
<li>Add <code>BODY</code> to print the body of the documented method definition as a Julia code block (<a href="">#54</a>, <a href="">#237</a>)</li>
<li>Add <code>NOTEMPLATE</code>, which stops a module's <code>@template</code> applying to the docstring it appears in. <code>TemplateOverride(category)</code> applies the template for another category instead (<a href="">#158</a>, <a href="">#240</a>)</li>
<li>Add the <code>ABSTRACTTYPES</code> template category for abstract types. A module without one documents abstract types with its <code>TYPES</code> template, as before (<a href="">#147</a>, <a href="">#241</a>)</li>
<li><code>SIGNATURES</code> and <code>TYPEDSIGNATURES</code> in the docstring of a macro print it as its caller writes it, such as <code>@m a b</code>. The <code>__source__</code> and <code>__module__</code> arguments and the inferred return type are left out. They printed nothing before. <code>METHODLIST</code> and <code>TYPEDMETHODLIST</code> list a macro the same way. For a vararg macro they printed its hidden arguments, and for any other macro nothing (<a href="">#262</a>)</li>
<li><code>SIGNATURES</code> and <code>TYPEDSIGNATURES</code> in the docstring of a struct list the constructors its definition creates. They printed nothing before (<a href="">#71</a>, <a href="">#245</a>)</li>
<li>Declare the interface for writing an abbreviation public on Julia 1.11 and later: <code>Abbreviation</code>, <code>format</code> and <code>interpolation</code>. A new guide covers it (<a href="">#86</a>, <a href="">#303</a>)</li>
<li>Declare the types that take abbreviation options public on Julia 1.11 and later, such as <code>MethodSignatures</code> and <code>TypeFields</code>. Each one appears on its topic's reference page (<a href="">#303</a>)</li>
<li>Add <code>TypeFields(; types, defaults)</code>, whose keywords match the other option types (<a href="">#303</a>)</li>
</ul>
<h3>Changed</h3>
<ul>
<li>Signatures leave out a return type inferred as <code>Any</code>, as they already did for <code>Nothing</code>. <code>-&gt; Any</code> says only that inference could not work out the type (<a href="">#301</a>, <a href="">#298</a>)</li>
<li>The manual splits into Examples and Reference sections with one page per topic. Each example page prints its source above the rendered docstrings, and new pages cover <code>PUBLIC</code>, <code>INSTANCES</code>, and <code>@template</code> with <code>DOCSTRING</code>. The package docstring is rewritten. A Setup page covers adding the package, templates, and Documenter. The docstrings of the package, <code>@template</code> and every abbreviation except <code>README</code> and <code>LICENSE</code> carry examples as doctests, which the docs build checks against the real output. They replace hand-written samples that had drifted from it (<a href="">#122</a>, <a href="">#215</a>)</li>
<li><code>SIGNATURES</code> prints an unnamed argument with a declared type as <code>::T</code>, as <code>TYPEDSIGNATURES</code> does, so <code>foo(::Val{N})</code> no longer prints as <code>foo(_)</code>. An untyped unnamed argument still prints as <code>_</code> (<a href="">#161</a>, <a href="">#235</a>)</li>
<li><code>TYPEDSIGNATURES</code> and <code>TYPEDMETHODLIST</code> print the declared type of each keyword argument, such as <code>f(x; n::Int64)</code>. An untyped keyword and a <code>kwargs...</code> keyword print without one (<a href="">#97</a>, <a href="">#244</a>)</li>
<li><code>FIELDS</code> and <code>TYPEDFIELDS</code> print each field's default value, such as <code>retries::Int64 = 3</code>, for structs defined with <code>Base.@kwdef</code> or a macro that uses the same syntax. <code>TypeFields(defaults = false)</code> hides them (<a href="">#182</a>, <a href="">#245</a>)</li>
<li><code>@template</code> applies a template when its docstring is defined, not when it is displayed, so a templated docstring no longer stores the documented expression in the package image. A docstring for a binding that does not exist yet keeps its template until display. Bindings documented together, such as <code>@doc &quot;...&quot; (f, T)</code>, each get the template for their own category, where they all used the last binding's (<a href="">#210</a>)</li>
</ul>
<h3>Deprecated</h3>
<ul>
<li><code>TypeFields(types::Bool)</code> is deprecated in favour of <code>TypeFields(types = ...)</code> (<a href="">#303</a>)</li>
</ul>
<h3>Fixed</h3>
<ul>
<li>Fix inferred return types printing the names inference gives the type parameters it cannot work out, such as <code>-&gt; Pair{_A, Int} where _A</code>. They print as their bound, <code>-&gt; Pair{&lt;:Any, Int}</code>, on Julia 1.3 and later (<a href="">#300</a>, <a href="">#297</a>)</li>
<li>Fix <code>TYPEDSIGNATURES</code> leaving out the return type of a callable such as <code>(e::E)(x)</code> and of a constructor written <code>T{P}(...)</code>. Before Julia 1.6 they still print without one (<a href="">#279</a>, <a href="">#296</a>)</li>
<li>Fix a wrapped signature with only keyword arguments printing <code>;</code> alone on its own line. It prints <code>f(;</code> on the first line. A signature without arguments no longer wraps, so a long return type follows <code>f()</code> (<a href="">#281</a>, <a href="">#295</a>)</li>
<li>Fix <code>METHODLIST</code> and <code>TYPEDMETHODLIST</code> in a parametric type's docstring leaving out the constructors written <code>T{P}(...)</code> (<a href="">#280</a>, <a href="">#294</a>)</li>
<li>Fix signatures printing a <code>where</code> bound that names another type parameter with <code>Array{T, 1}</code> where the source writes <code>Vector{T}</code>, such as <code>S&lt;:Vector{T}</code> (<a href="">#278</a>, <a href="">#293</a>)</li>
<li>Fix a world-age warning on Julia 1.12 and later when <code>@template</code> and a docstring expand together from running code, such as in one <code>macroexpand</code> call. Under <code>--depwarn=error</code> the docstring lost its template (<a href="">#277</a>, <a href="">#292</a>)</li>
<li>Fix <code>@template</code> skipping a docstring on a bare existing name, such as <code>&quot;...&quot; f</code> after <code>function f end</code>. The dotted form <code>&quot;...&quot; M.f</code> already got its template (<a href="">#276</a>, <a href="">#291</a>)</li>
</ul>
